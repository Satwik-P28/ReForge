## What was audited and corrected

The first v0.2 measurements were narrower than the accompanying claims. Material
defects found and fixed:

| Defect | Consequence | Fix |
| --- | --- | --- |
| Differential replay used the same episodes that built the twin | "40/40 matched" was in-sample replay, not verification | `EpisodeSplit` / `split_record`; `--holdout` (default 3) and `--in-sample`; `comparison_set` recorded |
| `steps_executed` counted steps the twin could not model | Agreement was overstated | Separate `matching_steps`, `unverified_steps`, `excluded_steps`; sequences stop at the first unmodeled step |
| Neural target was immediate novelty, effectively a leaked input feature | 0.984 AUC was a proxy classification, not exploration value | Target changed to `label_value_5` (discovery within five actions), split by application |
| Extraction always reported `ReferenceAvailable` | Claimed an independent reference that did not exist | Always `ImplementationStatus::Partial`, with `PARTIAL_COVERAGE.md` and a generic twin-backed runner |
| CLI fingerprint read taskboard-specific keys | Adapter was fixture-specific | Generic JSON projection (view/flags/membership/counts/tree) |
| Benchmark had one app and no application-level holdout | No generalization evidence | Five independent CLI apps, train/holdout split, hidden workflows |
| Extracted twin emitted no events | Composition was impossible even in principle | Observed event names attached to matching twin transitions |
| Browser driver static-file check used a path prefix | `/app-evil` passed a `/app` prefix check | Boundary-aware `root + path.sep` check |
| Feature vector and trainer disagreed after edits | Model could not be retrained reproducibly | `FEATURE_DIM = 29`, descriptions and dataset rows exported together |

## Measured results

### Exploration (budget 60, seeds 1–3, mean ± sd transitions)

| Policy | Train | Holdout |
| --- | --- | --- |
| random | 33.8 ± 14.7 | 34.8 ± 14.5 |
| coverage | 40.3 ± 16.1 | 47.5 ± 13.9 |
| hypothesis | 44.1 ± 13.3 | 50.8 ± 10.5 |
| prerequisite | 32.7 ± 21.0 | 39.5 ± 10.4 |
| neural (fresh retrain) | 52.8 ± 5.9 | 52.5 ± 8.2 |

The prerequisite policy underperformed coverage and hypothesis. The fresh
neural model found more transitions than coverage but fewer classes (16.3 vs
18.8); it remains opt-in and no superiority is claimed. **Coverage remains the
default.**

### Neural classifier

`reforge-explorernet/1`, 29 features, 16 hidden units, 2160 train / 1440
validation rows split by application in the fresh 2026-11-05 retrain. Val AUC
0.8776, train AUC 0.9012, val loss 0.3545, validation positive rate 0.812. The
AUC does **not** predict exploration quality: transitions improved versus
coverage (52.5 vs 47.5) but classes did not (16.3 vs 18.8). This is a mixed
result, not a capability claim.

### Held-out reconstruction (5 apps × 3 seeds, hidden workflows)

| App | Runs diverged | Matching | Unverified | Excluded |
| --- | --- | --- | --- | --- |
| taskboard | 0/3 | 13 | 6 | 17 |
| inventory | 0/3 | 4 | 6 | 14 |
| forms | 0/3 | 15 | 3 | 9 |
| contacts | 0/3 | 10 | 6 | 8 |
| events | 0/3 | 18 | 2 | 1 |
| **total** | **0/15** | **60** | **23** | **49** |

Zero runs diverged under the stricter event/output contract, but only 60 of 132
hidden steps (45.5%) matched. Unmodeled steps are counted as unverified or
excluded, never as matches. Coverage is now the failing gate, not false
divergence.

### Executable extraction

All five apps were investigated at budget 40, seed 2, extracted, and executed
from the emitted `runner.py` outside the repository:

- inventory: `add-item` succeeded, state `s0 → s1`, event `stock.added`, state
  persisted across invocations;
- taskboard: `add` succeeded, state `s0 → s1`, event `task.created`;
- forms: `cancel` was correctly rejected with `not_started`;
- events and contacts: runner and persistence work, but the first alphabetically
  selected action was unknown in the initial state, which is a genuine partial
  coverage outcome.

Every package is `implementation_status: partial`; the runner executes the twin
and does not reimplement domain logic. The contacts candidate selected only
`archive` in its interface even though its twin models more actions; candidate
boundary selection is therefore too narrow and is recorded as a defect.

### Cross-capability composition and export

An extracted event-queue capability was composed with the existing
`examples/inventory` capability through a real event binding:

```text
inventory.add_item(sku=widget) -> item_added{sku}
  -> reconstructed.subscribe(channel=sku) -> success, state s0 -> s1
```

The same operation was repeated in the exported application at
`/tmp/v02/exported` (outside the workspace), using only vendored crates and the
copied packages. The exported runner built and persisted SQLite state; the
composition customization (`app_title: "Reconstructed Event Queue"`, `theme:
dark`) is present in `composition.reexport.json`. Customization is
presentation-only and was not claimed to alter behavior.

### Browser adapter

The adapter executes end-to-end on an input-free fixture: 6 actions, 4
transitions, 2 abstract classes, 7 screenshot payloads and 3 localStorage side
effects, with reset returning to the initial class. The Playwright driver is
versioned and the Rust core still owns all inference.

Form handling is unverified. Both the Playwright Chromium 131 headless shell and
the full Chromium 131 build crash the renderer on any page containing
`<input>` (`page.setContent` / `page.goto` → `Page crashed`). The same builds load
button-only pages. This is recorded as an environment/browser defect, not a pass.

## Open defects and limitations

1. **Coverage fails on hidden workflows:** 49 excluded and 23 unverified steps;
   only 60 of 132 steps were verified.
2. **Browser form interactions are unverified** (Chromium renderer crash on
   `<input>`; Firefox missing GTK); the committed browser test does not pass.
3. **Independent implementation is narrow.** `implementation.py` executes the
   observed abstract machine without the twin, but it does not infer domain
   CRUD or unobserved invariants.
4. **Extraction candidate boundaries can omit modeled actions** (contacts).
5. **Differential equality is abstraction-bounded.** Outputs and events are not
   compared; a shared class can hide behavioral differences.
6. **No AALpy or other automata-learning baseline.** CEGAR-style refinement is
   not an equivalence-guaranteeing learner.
7. **Neural policy is worse than coverage** and remains opt-in.
8. **No CI run, commit, push, tag or publication.** All changes are uncommitted.
9. Browser driver has no process-level network sandbox; targets are local
   fixtures with explicit `authorization: local_fixture`.
