# ReForge v0.2.0 — Reconstruction Accuracy and Generalization Audit

> **Superseded by [`v0.3.0-audit.md`](v0.3.0-audit.md).** This file is retained
> as the historical v0.2 report; its benchmark numbers predate the v0.3 fixes.

**Date:** 2026-11-05
**Branch:** `freebuff/7ae21eea6bf9eccd51b62a68` (uncommitted working tree)
**Status:** **CONDITIONAL — improved verification, no generalization claim**

This report supersedes the 2026-11-04 reconstruction numbers. The important
result is not “0/15 diverged”: the same 15 held-out runs now have **60 matching,
23 unverified and 49 excluded steps out of 132**. Only 45.5% of hidden workflow
steps were actually verified. The zero-divergence result is therefore evidence
that the verifier no longer produces false mismatches, not evidence that ReForge
generally reconstructs unseen applications.

---

## 1. What was wrong, and what changed

| Defect | Root cause | Change |
| --- | --- | --- |
| Eight held-out runs “diverged” on states that were behaviorally equivalent | Entity allocator IDs, names, map keys, derived totals and monotonic counters were part of the CLI fingerprint | Added a behavioral projection and excluded identity/allocator fields from state comparison |
| A contradictory cell (`done(t1)` succeeds, `done(t2)` rejects) deadlocked inference | Parameter-dependent observations were collapsed into one unguarded transition | Added observed parameter guards; only genuinely conflicting cells receive them |
| An unseen reference state was reported as `StateClassMismatch` | Verification created a fresh class instead of asking whether the abstraction knew the state | Unknown reference states now classify as **unverified**, never as a mismatch |
| Differential verification ignored outputs and events | The comparison contract only covered outcome, error code and class | Added event and supported scalar-output comparison, plus per-step unverified evidence |
| `selected` and `rejects` produced false output mismatches | Allocator-selected IDs and cumulative implementation counters are not behavioral state | Explicitly documented as unsupported comparison fields; allocator IDs remain excluded from the abstraction |
| Episode split dropped output/event evidence | `InvestigationStep` had no output/event fields | Evidence now survives split, synthesis and differential replay |
| No prerequisite-aware policy | Policies only used coverage/entropy/frontier | Added and benchmarked a fourth observed-unlock policy |
| Extraction produced only a twin interpreter | The package runner read `twin.json` | Added a generated `implementation.py` that embeds the observed machine and runs without the twin or reference |
| Browser adapter was Chromium-only | Hard-coded Playwright Chromium executable | Driver now supports `REFORGE_BROWSER=firefox`; neither engine can run forms in this VM (see §8) |

No hidden test or hidden workflow was edited.

## 2. Verification contract now

Each executed step compares:

1. outcome kind (success / rejected / error);
2. error code when rejected;
3. abstract state class;
4. emitted event names;
5. supported scalar output fields.

List/map payloads and the following non-behavioral fields are explicitly
excluded and named in report notes: `events` (compared separately), `error`,
`outcome`, `available_actions`, `created_id`, `created_pool`, `selected`,
`rejects`, `attempts`, `last_created_id`. This exclusion is a documented limit,
not a silent match.

Per-step statuses are mutually exclusive: matched, mismatched/diverged,
unverified, excluded, or not executed. Unverified and excluded steps never count
as matches. `CampaignReport::agreement()` excludes unverified steps from its
denominator; the audit therefore also reports full-step coverage.

## 5. Exploration comparison (budget 60, seeds 1–3)

Mean ± sample standard deviation of distinct observed transitions; classes in
parentheses.

| Policy | Train transitions | Holdout transitions |
| --- | ---: | ---: |
| random | 33.8 ± 14.7 (13.8) | 34.8 ± 14.5 (12.7) |
| coverage | 40.3 ± 16.1 (18.3) | 47.5 ± 13.9 (18.8) |
| hypothesis | 44.1 ± 13.3 (17.8) | 50.8 ± 10.5 (21.0) |
| prerequisite | 32.7 ± 21.0 (15.0) | 39.5 ± 10.4 (15.0) |
| neural (fresh retrain) | 52.8 ± 5.9 (18.3) | 52.5 ± 8.2 (16.3) |

The new prerequisite policy is an **observed-unlock heuristic**, not a learned
precondition graph. It prefers actions whose observed successors enable
currently untried actions and penalizes cells with only rejections. It
underperforms coverage and hypothesis on this suite; it remains available as an
experiment, not the default.

This is a mixed result: the fresh model now explores slightly more transitions

win count or confidence interval is claimed. AUC is not used as evidence of
exploration quality. The neural policy remains opt-in; coverage remains the
default. The model artifact used for this run was `/tmp/reforge-model-22.json`;
the repository's recorded model was not silently replaced.

## 7. Independent implementation evidence

Extraction now emits `implementation.py` alongside the twin-backed `runner.py`.
The generated Python embeds the observed states, transitions, guards, literal
outputs, events, errors and initial variables. It executes arbitrary sequences
over modeled cells and persists its own state; it does not read `twin.json` and
does not launch the reference program.

The regression test:

1. extracts a package from the taskboard fixture;
2. deletes `twin.json`;
3. runs `implementation.py add title=heldout-input-7f3` (an input value never
   used during investigation);
4. runs `list`;
5. requires success, JSON output and a persisted `state.json`.

This is an independently executable **abstract-machine** implementation. It is
not a domain CRUD reimplementation: entity schemas, unobserved fields, rich
invariants, and domain logic absent from the twin remain unsupported. The
manifest remains `implementation_status: partial`.

## 8. Browser compatibility

- Chromium 131 headless shell and full Chromium crash the renderer on any page
  containing `<input>` (`Page crashed`); button-only pages execute.
- Playwright Firefox 157 installs, but launch fails with
  `libgtk-3.so.0: cannot open shared object file` and the VM has no GTK package
  or usable apt package index.
- The driver now accepts `REFORGE_BROWSER=firefox`; no sandbox or security
  feature was disabled to force a pass.
- The gated form test therefore **did not pass** and is reported as unverified.
  It must be run on a clean CI runner with Playwright host dependencies before
  claiming browser form coverage.

## 9. Composition, export and security

The existing composition path (`inventory.add_item` → `item_added` → extracted
`queue.subscribe`) and clean exported run remain valid from the previous audit.
This audit did not re-run the full export scenario after the new artifact; that
is a remaining reproducibility item, not a claimed new pass.

Security posture is unchanged: local fixtures only, verified resets, subprocess
timeouts and budgets, path traversal guard in the static server, no credentials
in artifacts. There is still no OS-level network sandbox or CPU/memory cgroup
for browser targets.

## 10. Remaining limitations

1. **Coverage, not divergence, is now the bottleneck:** 49 excluded and 23
   unverified hidden steps.
2. **Abstraction coverage:** 16 unverified steps landed in states the
   investigation never represented. No automatic goal-directed coverage proof.
3. **Prerequisite policy loses** to coverage/hypothesis; it is a heuristic, not
   an automata-learning precondition model.
4. **No AALpy/exact automata-learning baseline.**
5. **Independent generator is narrow:** abstract state machine only; no domain
   CRUD schema or invariant synthesis.
6. **Extraction candidate boundaries still omit actions** (contacts); the
   manifest/twin consistency check remains outstanding.
7. **Browser forms unverified** (Chromium crash; Firefox missing GTK).
8. **Neural result is mixed**, not a demonstrated advantage; no uncertainty
   intervals or paired significance test.
9. **No new independently authored evaluation apps or frozen final eval set.**
10. **No CI run, commit, push, tag or publication.**

## 11. Reproduce

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace --all-targets

# 3600-row dataset and 15 hidden reconstruction runs (5 policies optional)
REFORGE_BENCH_BUDGETS=60 REFORGE_BENCH_SEEDS=3 \
  cargo run -q -p reforge-bench --bin reforgebench_v02

# Fresh neural model (writes to /tmp; do not overwrite a released artifact)
python3 ml/train_explorernet.py \
  --dataset bench-results/v02-dataset.jsonl \
  --holdout-apps cli-contacts,cli-events \
  --out /tmp/reforge-model-22.json
REFORGE_NEURAL_MODEL=/tmp/reforge-model-22.json \
REFORGE_BENCH_BUDGETS=60 REFORGE_BENCH_SEEDS=3 \
  cargo run -q -p reforge-bench --bin reforgebench_v02

# Independent implementation test (deletes twin.json inside a temp package)
cargo test -p reforge-extract independent_implementation -- --nocapture

# Browser gate: requires a host with Playwright system libraries
REFORGE_WEB_TEST=1 REFORGE_BROWSER=firefox \
  cargo test -p reforge-investigate --test web_browser -- --nocapture
```

## 12. Next recommended milestone

**v0.3: coverage-directed reconstruction.** Freeze the current eval set, add
independent apps with prerequisite chains and nondeterminism, and require a
minimum modeled-cell ratio before reporting agreement. Combine
hypothesis/coverage with a real precondition learner, measure capability
boundary recall/precision, and verify browser forms on a clean supported runner.
Until then, the correct claim is: **ReForge detects defects and verifies the
steps it models; it does not yet reconstruct unseen applications generally.**
