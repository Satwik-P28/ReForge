# ReForge v0.3.0 — Reconstruction Accuracy and Generalization Audit

**Date:** 2026-11-05  
**Branch:** `freebuff/7ae21eea6bf9eccd51b62a68` (uncommitted working tree)  
**Status:** **CONDITIONAL — stronger verification and a frozen independent suite; no general reconstruction claim**

This report supersedes `v0.2.0-audit.md`. It records the v0.2 remediation, the
additional defects found while building the v0.3 suite, and the first evaluation
on two independently authored applications that were not used to tune the
original five-app benchmark.

The important result is not “zero divergences.” On the original v0.2 suite,
**61 of 132 hidden workflow steps matched (46.2%)**, 23 were unverified, 48 were
excluded because an earlier unverified step stopped the sequence, and no step
mismatched. On the new v0.3 suite, **16 of 72 steps matched (22.2%)**, 12 were
unverified, 44 were excluded, and no step mismatched. Unverified and excluded
steps are not successes.

## 2. Failure matrix and root causes

| # | Observed failure | Root cause | Resolution | Evidence |
| ---: | --- | --- | --- | --- |
| 1 | Held-out runs reported state-class mismatches for behaviorally equal states | Allocator IDs, titles, map keys, derived totals and monotonic counters were part of CLI state identity | Behavioral projection over status/quantity/cardinality; identity fields excluded | `crates/reforge-investigate/src/adapters/cli.rs`; v0.2 divergences 8 → 0 |
| 2 | Contradictory cells deadlocked inference | Parameter-dependent success/rejection observations were collapsed into one unguarded edge | Observed parameter guards for genuinely conflicting cells | `twin_synth.rs`; guard regression test |
| 3 | Unknown reference states were called mismatches | Verification created a fresh class instead of asking whether the abstraction knew the state | Unknown state is `UnverifiedCause::UnknownAbstractState`, never a mismatch | `reforge-diff` unverified evidence |
| 4 | Outputs and events were not compared | Differential contract covered only outcome, error code and class | Supported scalar outputs and event names compared per step | `crates/reforge-observe/src/stable.rs`; `reforge-diff` |
| 5 | Abstraction refinement had no effect | Refinement recorded a split but `class_of` still returned the coarse projection | Fingerprint digest overrides map refined concrete states to the new class | `abstraction.rs`; refinement regression test |
| 6 | Taskboard capability omitted observed actions | Candidate discovery used a narrower surface than the observed CLI actions | CLI targets use one capability surface; coverage metrics added | `reforge-extract/src/discover.rs`; capability audit |
| 7 | Contacts portability audit failed | A domain state key (`contacts`) was treated as source-app identity | State descriptions excluded from identity scan | `portability.rs` |
| 8 | Ticket portability audit failed | A behavioral output field (`tickets`) was treated as source-app identity | Identity scan limited to twin metadata (`id`, `name`, `description`) | `portability.rs`; output-field regression test |
| 9 | Prerequisite policy collapsed to ~1.7 transitions | A self-loop (`list` returning to the same class) was credited with unlocking every untried action in that class | Self-loops do not count as downstream unlocks | `prerequisites.rs`; self-loop regression test |
| 10 | Prerequisite policy then oscillated between two seen states | A tried action leading to a state with untried actions outranked every local untried action | Local untried cells dominate; prerequisite evidence directs choices after local exhaustion | `policy.rs`; v0.3 prerequisite 1.7 → 60.0 train |
| 11 | Ticket hidden workflow diverged on `close` | Two rejection codes from one abstract cell (`no_such_ticket`, `not_assigned`) were merged into one transition; synthesis chose the alphabetically first code | Transition identity includes the error code; multi-error cells receive parameter guards | `model.rs`, `twin_synth.rs`; error-code guard regression test |
| 12 | Some hidden steps remain unverified | Coverage/input-space gaps: concrete quantities or states never exercised by the investigator | Reported explicitly; hidden workflows were **not** edited | v0.2/v0.3 unverified details |
| 13 | Browser form test unavailable | Chromium renderer crash on `<input>`; Firefox missing `libgtk-3.so.0`; no usable package installation | Security not weakened; test remains unexecuted | Prior environment evidence |
| 14 | Neural scorer gives no demonstrated exploration advantage | Ranking learned from novelty-correlated features; no ranking/sequential objective or AALpy baseline | Reported as mixed; neural remains opt-in | §7 |
| 15 | Independent implementation is still narrow | Generator emits the observed abstract machine, not domain CRUD/schema/invariants inferred from behavior | Clearly labeled partial | §6 |

No hidden workflow from the original v0.2 suite was modified. The two v0.3
hidden files were authored with the new applications and frozen before the
final benchmark run.

### Minimal divergence trace fixed in this cycle

```
tickets: assign(t1) -> create(alpha) -> close(t1)
reference: rejected / not_assigned
twin (before fix): rejected / no_such_ticket
```

The two codes came from the same `(class, action, rejected)` key with different
query bindings: one stale purged ID and one live ticket. Error codes are now part
of transition identity, and each guarded branch replays the code observed for
its binding.

### Minimal policy-collapse trace fixed in this cycle

```
s0: add-book -> s1
s1: detail -> s2
s2: list -> s1
```

`detail` and `list` repeatedly scored the other state's untried cells as an
unlock, so the policy never exercised those cells. Local untried cells now take
priority; the v0.3 prerequisite mean rose from 1.7 to 60.0 transitions on train.

## 6. Independent implementation and composition

`implementation.py` is generated from the extracted twin and embeds the observed
states, guards, outputs, events, errors and initial variables. It persists its
own state and does not read `twin.json` or launch the reference program.

Verified:

```text
cargo test -p reforge-extract --test extraction independent
  1 passed: independent_implementation_runs_held_out_inputs_without_the_twin
cargo test -p reforge --test e2e_composition
  5 passed
```

The independent test deletes `twin.json`, executes an input value not used during
investigation, and verifies persistence. The composition test propagates a
`create_task` event from inventory into tasks, checks the created `SKU-1`, and
reopens SQLite to verify the state survives restart.

This is an independently executable **abstract machine**, not a domain CRUD
generator. Typed domain schemas, rich invariants, and behavior absent from the
twin remain unsupported; the package remains `partial`.

## 11. Remaining limitations

1. **Coverage is the bottleneck.** 48/132 v0.2 and 44/72 v0.3 hidden steps were
   excluded after an unverified step; 23 and 12 steps were unverified.
2. **No semantic precondition learner.** The graph is observed evidence, and
   blocked cells remain explicitly unknown.
3. **Independent implementation is narrow.** It executes the observed machine,
   not reconstructed domain CRUD or rich invariants.
4. **Browser forms unverified.** The environment lacks a working Playwright
   browser/runtime stack.
5. **Neural guidance is mixed and optional.** No demonstrated advantage against
   strong deterministic baselines; no AALpy baseline.
6. **Capability metrics cover action boundaries only**, not semantic fidelity.
7. **No CI run, commit, push, tag or publication.**
8. **No OS-level network sandbox** for target or browser execution.

## 12. Next recommended milestone

**v0.4: input-space and state-coverage reconstruction.** Add goal-directed
parameter exploration (quantity boundaries, stale/live entity IDs, and
destructive transitions), measure full workflow correctness against frozen
hidden suites, and require an explicit modeled-cell ratio before reporting
agreement. Add a real automata-learning baseline and browser-form verification
on a supported runner. Do not expand the architecture again until coverage, not
divergence, is demonstrated to improve on held-out applications.
