## Executable extraction

`runner.py` remains the twin interpreter. `implementation.py` is a generated
Python executable that embeds the observed machine, guards, outputs, events,
errors and variables, and persists its own state. The regression test deletes
`twin.json` and executes a held-out input value successfully.

This does **not** implement domain CRUD that was not observed, and it is not a
general application reconstructor. The package remains `partial`.

## Browser result

- Chromium 131: renderer crash on any page containing `<input>`.
- Firefox 157: installs, but launch fails on missing GTK (`libgtk-3.so.0`); the
  VM has no usable apt package index.

- The required form entry/submission/persistence/reset acceptance test remains
  **unexecuted**.

## Remaining limitations

1. Coverage is the bottleneck: 49 excluded and 23 unverified hidden steps.
2. Extraction candidate boundaries can still omit modeled actions.
3. The independent implementation is an abstract machine, not a domain clone.
4. Browser forms are unverified.
5. No AALpy-style automata-learning baseline.
6. No newly authored frozen evaluation set or CI browser run.
7. No commit, push, tag or publication.
