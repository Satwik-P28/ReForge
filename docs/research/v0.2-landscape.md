# v0.2 Landscape: Learning Software Behavior Without Trusting the Learner

**Date:** 2026-11-04
**Scope:** the research and tooling landscape that shaped ReForge v0.2
("investigate → model → reconstruct → verify").

This document records what exists, what it actually provides, and what ReForge
therefore does and does not do. Citations were checked against the sources
listed; claims we could not verify are labelled **UNVERIFIED** and were not used
to justify a design decision.

---

## 1. Research that motivates the milestone

| Work | Identifier | What it actually contributes |
| --- | --- | --- |
| ProgramDistill | arXiv 2609.18805 (project blog, Sept 2026) | Distils program behavior into an executable model rather than a textual description. Supports the "reconstruct an executable twin, not a summary" position. |
| Trace2World | arXiv 2610.30792 | Builds an executable environment model from interaction traces. Reinforces trace-driven reconstruction and exposes the same hard question we hit: which abstraction makes two runs "the same state". |
| WebAnything | arXiv 2610.37786 | Agentic reconstruction of web application behavior. Demonstrates feasibility for web targets; also demonstrates why a harness (authorization, budgets, resets) is not optional. |

All three were verified to exist and to be described accurately above. None of
them publishes a checkable artifact we could vendor; we therefore cite them as
motivation, not as dependencies.

**Design consequence:** ReForge v0.2 implements its own observation IR, active
learner, abstraction, twin synthesis, and differential verifier in Rust. It does
not claim to reproduce any result from those papers, and reports no comparison
against their systems.

## 2. Learning and verification tooling

| Tool | License | What it provides | Why we did not embed it |
| --- | --- | --- | --- |
| AALpy | MIT (Python) | Active automata learning: L*, KV, L#, hW in the released API. | **No TTT in the released API** (checked). Pulling a Python runtime into the core would make "works without ML/Python" false. We implemented a deterministic active learner in Rust. |
| REA (`morluto/rea`) | MIT | Automata-learning toolkit. | The commonly cited `StackeredSAS/rea` does **not** exist; the real project is `morluto/rea`. Not embedded because our learning loop must share the engine's budgets, resets, and evidence log. |
| Joern | Apache-2.0 | Static code property graphs. | Static-only; v0.2 is about observed behavior. Candidate for a future static/dynamic hybrid. |
| Z3 | MIT (+ `z3` crate, MIT) | SMT solving. | v0.2 synthesizes no guards or invariants, so there is nothing to solve. Documented as future work rather than wired in unused. |
| Kani 0.68.0 | MIT / Apache-2.0 | Bounded Rust model checking; needs a pinned nightly + CBMC. | Adds a nightly toolchain and a C dependency to the release path for properties we do not yet state. |
| `libafl_libfuzzer` | MIT / Apache-2.0 | Fuzzing. (`cargo-libafl` is superseded.) | Useful for input generation later; not needed to learn a finite CLI alphabet. |
| WASI 0.3 / Component Model | — | WASI 0.3 became stable on 11 Jun 2026; the Component Model is pre-1.0. | The export target stays `local-web`; the Component Model is not stable enough to be a compatibility promise. |

## 3. What this means for ReForge

1. **Deterministic core, optional ML.** The investigator, abstraction, twin
   synthesizer, extractor, and differential verifier are pure Rust with no Python
   and no model. The neural scorer is an optional ranking layer whose absence
   changes nothing about what is recorded.
2. **Evidence over prediction.** Papers describe learned models; ReForge records
   *which observation* supports *which transition*, and keeps unobserved and
   contradictory cells explicit.
3. **The abstraction is the contract.** Every system in this space implicitly
   chooses when two states count as equal. ReForge makes that choice explicit
   (ADR 0011) and states it in every verification report.
4. **The benchmark must be able to lose.** Our neural ablation *does* lose
   (47.0 vs 55.5 observed transitions, and 20.1 vs 27.7 classes, on paired runs
   across five apps). That result is published in the technical report and
   readiness report rather than tuned away.

## 4. Open questions we did not answer

- Cross-platform reconstruction (web/desktop) — a Playwright adapter now exists
  and executes, but form input is unverified because Chromium crashes on
  `<input>` in the evaluation environment.
- Guard/invariant synthesis with SMT — deliberately deferred; an invented guard
  is a fabricated fact.
- Multi-target benchmarks — v0.2 evaluates five independent CLI apps with an
  application-level holdout. No hidden run diverged, but only 60 of 132 steps
  were verified (23 unverified, 49 excluded), so no generalization claim is made.
