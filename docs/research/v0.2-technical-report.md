# ReForge v0.2 Technical Report — Generalization, Neural Guidance, and Reconstruction

**Date:** 2026-11-04
**Version:** 0.2.0 (unreleased working tree)
**Status:** implemented, measured, and partially failing its acceptance gates

---

## 1. Scope

v0.2 adds a deterministic investigation and reconstruction pipeline on top of the
v0.1 capability runtime:

```text
reference app -> adapter -> Observation IR 2.0.0 -> abstraction/refinement
              -> active policy -> behavioral twin -> extraction package
              -> composition -> differential verification -> export
```

The v0.1 packages, Composer, runtime, verifier and exporter are preserved. The
new work is additive and the full workspace passes 124 tests.

The headline finding is negative: the pipeline works end to end on supported
targets, but its reconstructions do not generalize reliably to unseen workflows.
Eight of fifteen held-out runs diverged. This report keeps that result central.

## 2. Audited method

### 2.1 Observation

Each adapter emits an `Observation` with before/after fingerprints, normalized
outputs, side effects, errors, timing, environment, completeness and reset
provenance. Payloads are content-addressed. Normalization rewrites volatile
values unless the key is protected, so state that matters cannot be normalized
away.

The CLI adapter runs a declared subprocess with a timeout, parses one JSON
envelope, captures filesystem state and verifies a copy-pristine reset. The
fingerprint is generic over JSON (view, flags, membership, counts, tree) rather
than reading application-specific keys.

The browser adapter speaks `reforge-web-driver/1` over JSON lines to a Node
Playwright driver. The driver owns the browser, local static server, context
reset, ARIA snapshot, DOM/form/link extraction, localStorage, console errors,
network metadata and screenshots. The Rust core owns every inference decision;
no policy or abstraction was reimplemented in JavaScript. Requests are
serialized, timed out, and the child process is killed on drop.

### 2.2 Abstraction and refinement

State identity is a projection over declared keys (`view`, `flags`,
`membership`, `actions`). A conflicting outcome for the same cell refines the
class and records the refinement. This is CEGAR-style refinement, not an
automata-learning algorithm with membership and equivalence queries, and it
carries no equivalence guarantee.

### 2.3 Policies

| Policy | Rule |
| --- | --- |
| `random` | uniform over resolvable actions |
| `coverage` | prefer unexplored cells, then rare outcomes |
| `hypothesis` | novelty + weighted conflict for untried cells; success-rate tiebreak |
| `neural` | hypothesis ranking replaced by a 29-feature MLP score when an artifact loads |

Coverage is the default. Neural inference is optional, versioned
(`reforge-explorernet/1`) and replaceable.

### 2.4 Twin synthesis and extraction

Only observed cells become transitions with `Certainty::Observed`. Conflicts
become `Certainty::Contradictory` and are surfaced, not resolved by guessing.
Unexercised cells are `UnknownDecl`; no guards or invariants are invented.

Extraction discovers candidate boundaries from the observed state graph,
synthesizes contracts from observed errors and notes, attaches observed event
names to matching transitions, and emits:

- `manifest.json` (always `implementation_status: partial`),
- `twin.json`,
- `runner.py` (twin-backed executor with persisted abstract state),
- `PARTIAL_COVERAGE.md` (unmodeled cells, excluded behavior),
- `EXTRACTION.md` and content-addressed evidence.

The runner is deliberately generic: it loads `twin.json`, applies the transition
for the current abstract state, persists state and history, returns `unknown`
for unmodeled cells and `hypothesis_conflict` for contradictory ones. It is not
an independent reimplementation of the source application.

### 2.5 Differential verification

Reference and twin replay the same action program from a verified reset. Per step
the differ compares outcome, error code and abstract class. Steps the twin cannot
model stop the sequence and are counted as **unverified**, never as matches.
Minimization removes chunks of the prefix while preserving the divergence.
Held-out campaigns use episodes that were not used to build the twin; in-sample
replay is available only behind `--in-sample` and is labelled as such.

### 2.6 Composition and export

Observed event names on twin transitions let the generic Composer bind an
extracted capability. In the demonstrated composition, an existing inventory
`add_item` emits `item_added{sku}`, which maps to the extracted event queue's
`subscribe(channel)`. The operation succeeds and persists `s0 → s1`.

Export vendors the runtime crates and copies both packages. The exported app was
built and executed outside the workspace, persisted SQLite state and reproduced
the cross-capability operation.

## 3. Measurements

### 3.1 Exploration benchmark

Five independent CLI apps; budgets 30 and 60; seeds 1–3; means are over all
runs at both budgets. Values are transitions and abstract classes.

| Policy | Train transitions | Train classes | Holdout transitions | Holdout classes |
| --- | --- | --- | --- | --- |
| random | 33.8 ± 14.7 | 13.8 | 34.8 ± 14.5 | 12.7 |
| coverage | 40.3 ± 16.1 | 18.3 | 47.5 ± 13.9 | 18.8 |
| hypothesis | 44.1 ± 13.3 | 17.8 | 50.8 ± 10.5 | 21.0 |
| prerequisite | 32.7 ± 21.0 | 15.0 | 39.5 ± 10.4 | 15.0 |
| neural (fresh) | 52.8 ± 5.9 | 18.3 | 52.5 ± 8.2 | 16.3 |

Coverage, hypothesis and the fresh neural policy are close on holdout
transitions; hypothesis leads on classes. The prerequisite heuristic loses. No
policy has a demonstrated general advantage.

### 3.2 Neural evaluation

The original target (`label_new_behavior`) was identical to an input feature and
was removed. The replacement is `label_value_5`: whether a new behavior or state
is discovered within the next five actions, computed post-hoc within an episode.
Rows are split by **application**, never by row or run.

| Metric | Value |
| --- | --- |
| Rows (train / validation) | 2160 / 1440 (fresh 2026-11-05 run) |
| Features / hidden units | 29 / 16 |
| Train AUC | 0.9012 |
| Validation AUC | 0.8776 |
| Validation loss | 0.3545 |
| Holdout positive rate | 0.812 validation |
| Neural vs coverage transitions (holdout) | 52.5 vs 47.5 |
| Neural vs coverage classes (holdout) | 16.3 vs 18.8 |
| Neural vs hypothesis transitions / classes | 52.5 / 16.3 vs 50.8 / 21.0 |

The fresh result is mixed, not a demonstrated advantage: neural guidance finds
more transitions than coverage but fewer abstract classes than either coverage
or hypothesis. No paired win count or confidence interval is claimed. The
policy remains opt-in, and the AUC is not treated as evidence of exploration
quality.

### 3.3 Held-out reconstruction

```text
app          runs  diverged  matching  unverified  excluded
taskboard     3       0          13         6         17
inventory     3       0           4         6         14
forms         3       0          15         3          9
contacts      3       0          10         6          8
events        3       0          18         2          1
total        15       0          60        23         49
```

Zero runs now diverge under the stricter event/output contract, but only 60 of
132 hidden steps (45.5%) match. Sixteen unverified steps land in states absent
from the abstraction; seven have no modeled transition from a known class. The
verifier is doing its job — it refuses to count unmodeled behavior as agreement.
Run details are in `docs/release/v0.2.0-audit.md`.

### 3.4 Extraction execution

At budget 40, seed 2, all five apps produced loadable packages with
`implementation_status: partial`. Each package also carries a generated
`implementation.py` that embeds the observed machine and runs without
`twin.json` or the reference. Executing `runner.py` outside the repository:

- inventory `add-item` → success, `s0 → s1`, event `stock.added`, persisted;
- taskboard `add` → success, `s0 → s1`, event `task.created`, persisted;
- forms `cancel` → rejected `not_started` (observed behavior);
- events/contacts → runner operational; the first action was unknown in the
  initial state, correctly reported as partial coverage.

Contacts exposed only `archive` in its declared interface, revealing a candidate
boundary defect: the package can declare fewer actions than its twin models.

### 3.5 Browser

Executed on a button-only fixture: 6 actions, 4 transitions, 2 classes, 7
screenshot payloads, 3 localStorage side effects, reset to the initial class.
The committed `web-board` fixture contains form inputs and crashes the Chromium
131 renderer on `page.goto`/`setContent`, even with no app script. Playwright
Firefox 157 installs but cannot launch because the VM lacks `libgtk-3.so.0`.
Form filling and submission remain unverified; no security feature was disabled
to force a result.

## 4. What the evidence supports

Supported:

- deterministic CLI investigation with evidence and verified resets;
- partial behavioral twins that execute and persist state;
- a real Composer path from an existing capability to an extracted one;
- defect detection in differential verification, with counterexamples;
- application-level evaluation with hidden workflows and a negative neural result;
- portable export that builds and runs outside the workspace.

Not supported:

- general reconstruction of unseen workflows (only 60/132 hidden steps verified);
- domain CRUD reimplementation (the independent artifact is an abstract machine);
- full browser coverage (form inputs unverified);
- superiority of neural guidance (mixed result);
- full behavioral equivalence (payloads, timing and named artifacts are excluded);
- any "clone any application" framing.

## 5. Limitations

1. Abstraction-bounded equality can merge states with different future behavior.
2. Unexercised cells dominate; no guard or invariant synthesis.
3. Candidate boundary selection can omit modeled actions.
4. Event payloads are not modeled, so extracted capabilities can consume but not
   source rich event bindings.
5. No AALpy-style equivalence approximation or exact automata-learning baseline.
6. Browser form path untested; no network sandbox.
7. No CI run, commit, tag or publication.

## 6. Reproduction

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace --all-targets

target/debug/reforge investigate --spec fixtures/v02/cli-inventory/target.json \
  --out /tmp/v02/record.json --budget 40 --seed 2
target/debug/reforge extract --record /tmp/v02/record.json --out /tmp/v02/pkg
target/debug/reforge differential --record /tmp/v02/record.json \
  --spec fixtures/v02/cli-inventory/target.json --holdout 3

target/debug/reforgebench_v02
python3 ml/train_explorernet.py --dataset bench-results/v02-dataset.jsonl --out ml/model.json
```

Benchmark artifacts: `bench-results/v02-latest.json`,
`bench-results/v02-dataset.jsonl` (3600 rows in the latest run). The fresh model
was trained to `/tmp/reforge-model-22.json`; the repository's `ml/model.json`
remains the earlier recorded artifact.
